# Scheduled evidence reports

Open an OpenWRT server's **Reports** tab. The default run time is **03:00
Europe/London**, configurable with an IANA timezone. **Process now** queues work
on the recorder maintenance process. The recorder must be running, even if the
router's collection is paused. The Reports tab shows progress, last success,
failures, the next scheduled run and retained storage.

A report covers the previous local calendar day, using UTC timestamps internally
and timezone-labelled local times for presentation. Spring/autumn daylight-saving
days contain 23/25 hours. An ambiguous scheduled time runs once; a nonexistent
spring time advances across the gap. Interrupted or missed work is retried.

## What is retained

The archive writer creates compact facts in the same SQLite transaction that
acknowledges archived readings. Counts, RTT sums and fixed histogram buckets,
one-second observation bins, router measurement ranges, all incident markers,
logs/gaps and selected supporting excerpts survive raw-cache pruning. Adjacent
minute groups of the same condition are consolidated for presentation; this does
not assert uninterrupted impairment. Selected evidence carries original times,
run/sample identities, archive identity/sequence and content digests.

Completed call analyses are stored independently of the raw-test table and the
200-report interactive cache. New analyses retain every identified episode and
at least one supporting observation per episode. Historic reports generated by
older analyzers can be incomplete; their omitted-episode/quality information
remains visible. Historic tests already deleted before this upgrade cannot be
reconstructed from call summaries that no longer exist.

Legacy raw archives are streamed once, at their committed byte checkpoints.
Partial writes, corrupt gzip streams and inconsistent counts prevent cleanup.
The worker does not use an external AI service or perform extra network tests.

## Publication and cleanup

Raw archive files rotate at the configured processing time, not midnight. Their
names show the cycle's UTC start date. They can contain measurements from other
days because measurement time is independent of archive receipt time.

The scheduled worker imports any legacy facts, captures available call
conclusions, revises affected previous days, verifies and commits reports, then
runs age/size cleanup. Failed publication retains the raw archives. Changes
arriving while publication runs keep a revision marker for the next run. The
live raw SQLite cache still follows its existing age/row/payload limits throughout
the day; readings are protected until their archive/fact checkpoint commits.

- Raw file limits stay in **Recording settings** (existing settings are preserved).
- Full call-test evidence defaults to **7 days / 1024 MiB** per router.
- Reports, independent call conclusions and compact facts default to
  **365 days / 512 MiB** per router. Whole older days are retired together.
  Late arrivals do not recreate days already retired by the byte budget.
- Running tests and the newest daily report are protected. The UI explicitly
  reports when pending facts or protected data exceed the summary budget.
- Pausing processing pauses raw archive cleanup. Turning raw archiving off
  removes its protection from raw-cache cleanup and limits future report coverage.
- Recovery copies are visible in storage accounting but are never deleted by
  telemetry retention. Docker images and externally stored container logs are
  outside the data-volume total.

SQLite may reuse pages without shrinking its file. The storage meter separates
reusable database pages from live contents, counts archives/recovery/temp files,
and shows host free space. Below 5 GiB free is a warning; below 1 GiB is critical.
These are visible capacity warnings, not an automatic destructive disk cleanup.

## Daily, weekly and custom HTML

Select one day, a Monday–Sunday week or custom inclusive dates. Period totals
combine counts, sums and histogram populations; percentages and means are
recomputed, never averaged across days. Call tests spanning midnight appear in
the relevant daily timelines and once in the period register. Their whole-test
receiver summaries are not presented as calendar-day loss rates.

Reports include a timeline, supporting excerpts, per-path statistics, router
measurement statistics, source provenance and coverage limits. A recording in
one second does not imply a full minute of coverage. Empty or missing days are
not zero-loss or healthy days. Incident markers, call episodes and grouped
observations can overlap and are not independent outage counts. Correlation
never establishes root cause or actual FaceTime/Teams/Zoom call quality.

HTML is escaped, authenticated, private and printable using browser Print / Save
as PDF. It uses embedded CSS and no server-side PDF software. Readers can view
reports; administrators configure processing or queue runs. Custom ranges are
limited to 366 dates and 128 MiB of decoded report content; individual days have
bounded storage/processing allowances, with a visible error and protected raw
sources if those are exceeded. Detailed year-long exports may require smaller
ranges.

## Validation

Synthetic tests cover DST, schedule changes, late evidence, idempotent reprocessing,
archive checkpoint failures/CRC errors, publication failure, cleanup protection,
weighted totals, authorization and escaping. Browser tests exercise date selection,
refresh preservation, processing settings, mobile layout and print styles.
Live-host processing throughput is separate from these local checks.
